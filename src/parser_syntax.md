# UartSniffer 协议规则语法

UartSniffer 通过一个文本规则文件描述串口报文格式。每行一条规则，包含**过滤器**（匹配条件）和**字段**（解码描述）。

```
{<filter>, ...}  [<field>]  [<field>]  ...   # <rule-label>
```

注释：以 `#` 开头的整行被忽略；行内 `#` 之后的内容作为该规则的标签（rule-label）。
空行和以 `;` 开头的行也被忽略。

---

## 1. 过滤器 `{ ... }`

过滤器决定一条报文是否命中该规则。多条规则按文件顺序匹配，**第一条命中的规则**被用于解码。
一组花括号内可写多个过滤器，用逗号分隔，例如 `{len=8, idx0=0xAA}`。

| 语法              | 含义                                    | 示例                |
| ----------------- | --------------------------------------- | ------------------- |
| `len=<N>`         | 报文长度**等于** N                      | `{len=8}`           |
| `minlen=<N>`      | 报文长度 ≥ N                            | `{minlen=4}`        |
| `maxlen=<N>`      | 报文长度 ≤ N                            | `{maxlen=32}`       |
| `idx<N>=<V>`      | 第 N 个字节等于 V（V 支持 0x 十六进制） | `{idx0=0xAA}`       |
| `first=<V>`       | 第一个字节等于 V（`idx0=` 的别名）      | `{first=0xAA}`      |
| `last=<V>`        | 最后一个字节等于 V                      | `{last=0x55}`       |

> 提示：要匹配一个完整的帧头帧尾结构，常见组合是 `{first=0xAA, last=0x55, minlen=4}`。

---

## 2. 字段 `[ ... ]`

字段的完整语法：

```
[<type>(<label>)<modifier>...]
```

- `type` 必填，决定字节宽度和原始解码方式。
- `(<label>)` 可选，给该字段一个可读的名字。
- `modifier` 可选，可重复，用来做缩放、加偏置、单位标注、显示格式或枚举映射。

### 2.1 基本类型

| 类型     | 字节数 | 说明                          |
| -------- | ------ | ----------------------------- |
| `u8`     | 1      | 无符号 8 位                   |
| `s8`     | 1      | 有符号 8 位                   |
| `u16`    | 2      | 无符号 16 位（按全局端序）    |
| `s16`    | 2      | 有符号 16 位                  |
| `u32`    | 4      | 无符号 32 位                  |
| `s32`    | 4      | 有符号 32 位                  |
| `float`  | 4      | IEEE-754 单精度浮点           |
| `double` | 8      | IEEE-754 双精度浮点           |

### 2.2 复合 / 字符串类型

| 类型      | 长度 | 显示                                                  |
| --------- | ---- | ----------------------------------------------------- |
| `array-N` | N    | 显示十六进制字节序列                                  |
| `str-N`   | N    | 显示为可打印 ASCII 字符串（不可打印字符替换为 `.`）   |
| `bcd-N`   | N    | 每字节解码为两位 BCD 十进制数字，拼接显示（例 `230528`）|

### 2.3 端序后缀

在数据类型尾部加 `le` 或 `be` 可强制小端 / 大端，覆盖全局端序设置：

```
[u16le(temp)]     # 强制小端
[s32be(stamp)]    # 强制大端
```

不带后缀时使用 CLI/GUI 全局配置的端序。

### 2.4 字段修饰符

修饰符紧跟在 `(<label>)` 后（或紧跟类型后，若没有 label）。可以以任意顺序、任意次数出现。

| 修饰符        | 作用                                                              | 示例                              |
| ------------- | ----------------------------------------------------------------- | --------------------------------- |
| `@<num>`      | **缩放因子**：显示值 = 原始值 × num                               | `[u16(vol)@0.1]`                  |
| `+<num>`      | **正偏置**：在缩放之后加上 num                                    | `[s16(temp)@0.1+(-40)]` 或 `+25`  |
| `-<num>`      | **负偏置**：在缩放之后减去 num                                    | `[s16(temp)-40]`                  |
| `=<unit>`     | **单位**：附加在显示值之后                                        | `[u16(vol)@0.1=V]`                |
| `%<c>`        | **显示格式**：见下表                                              | `[u8(flags)%b]`                   |
| `\|<v>=<name>`| **枚举映射**：原始值等于 v 时显示 name（可重复）                  | `[u8(state)\|0=idle\|1=run]`      |

> 计算顺序：`显示值 = 原始值 × scale + offset`

#### 显示格式 `%<c>`

| 格式 | 含义                | 输出示例（u8 = 65） |
| ---- | ------------------- | ------------------- |
| `d`  | 仅十进制            | `65`                |
| `x`  | 仅十六进制          | `0x41`              |
| `o`  | 八进制              | `0101`              |
| `b`  | 二进制              | `0b01000001`        |
| `c`  | ASCII 字符          | `'A'  (0x41)`       |

未指定时，整数同时显示十进制和十六进制（如 `65  (0x41)`）。

#### 枚举映射

```
[u8(state)|0=idle|1=running|2=error|3=halt]
```

当原始值匹配某个枚举键时，会在末尾追加 `(name)`。例如收到 `0x02` 会显示：

```
  2  (0x02)  (error)
```

## 3. 完整示例

### 3.1 简单电压电流帧

```
# 8 字节定长帧：AA + u16 电压(0.1V) + u16 电流(0.01A) + u8 状态 + u8 校验
{len=8, first=0xAA} [u8(hdr)%x] [u16(voltage)@0.1=V] [u16(current)@0.01=A] [u8(state)|0=idle|1=run|2=err] [u8(cksum)%x]  # power-status
```

收到 `AA 04 D2 00 7B 01 5A` 之后的解码（节选）：

```
| [0000]  hdr               AA                        0xAA
| [0001]  voltage           04 D2                     1234  (0x04D2)  -> 123.4 V
| [0003]  current           00 7B                     123  (0x007B)  -> 1.23 A
| [0005]  state             01                        1  (0x01)  (run)
| [0006]  cksum             5A                        0x5A
```

### 3.2 温度（带偏置）

```
# DS18B20 温度寄存器：s16 原始值 × 0.0625 °C
{minlen=2} [s16le(temp)@0.0625=°C]  # ds18b20
```

### 3.3 BCD 时间戳

```
# 6 字节 BCD：YY MM DD HH MM SS
{len=6, first=0x20} [bcd-1(year)] [bcd-1(month)] [bcd-1(day)] [bcd-1(hour)] [bcd-1(min)] [bcd-1(sec)]  # rtc-time
```

### 3.4 ASCII 命令应答

```
{first=0x3E, last=0x0D} [u8(prompt)%c] [str-8(cmd)] [u8(cr)%x]   # cli-ack
```

### 3.5 位标志

```
{len=2, first=0xF0} [u8(hdr)%x] [u8(flags)%b]  # gpio-state
```

输出会以 `0b00010110` 的形式展示该字节的每一位。

## 4. 解析器限制

| 项             | 上限                                                        |
| -------------- | ----------------------------------------------------------- |
| 总规则条数     | `MAX_RULES = 64`                                            |
| 每条规则字段数 | `MAX_FIELDS = 64`                                           |
| 每条规则过滤器 | `MAX_FILTERS = 16`                                          |
| 标签长度       | `MAX_LABEL_LEN = 64` 字节                                   |
| 单位长度       | `MAX_UNIT_LEN = 12` 字节                                    |
| 枚举条数       | `MAX_ENUM_ENTRIES = 16` 个                                  |
| 枚举名长度     | `MAX_ENUM_NAME = 24` 字节                                   |
| 单行长度       | `MAX_LINE_LEN = 512` 字节                                   |

---

## 5. 匹配算法

1. 收到一帧后，按文件顺序遍历所有规则。
2. 对每条规则，依次检查所有过滤器；任一过滤器不通过则跳过该规则。
3. 第一条全部通过的规则被选中，按其字段列表依次解码报文。
4. 若没有规则命中，输出 `(no rule matched)`。
5. 若字段定义的总字节数小于报文长度，多出的部分作为 `(trailing)` 显示。
